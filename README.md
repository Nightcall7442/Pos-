# Qwik — POS для торговой точки

Система для магазина и общепита: касса, склад с себестоимостью, техкарты,
кассовые смены и отчётность. Всё работает в браузере — ставить на кассу
ничего не нужно.

- **Сайт:** [www.qwik.uz](https://www.qwik.uz)
- **Панель управления:** [admin.qwik.uz](https://admin.qwik.uz)
- **Касса:** [pos.qwik.uz](https://pos.qwik.uz)

---

это запросы на свой же домен — отдельной настройки CORS в обычной работе
не требуется.

## Возможности

**Касса.** Категории и поиск, весовой товар (цена считается от веса), столы,
клиент, заказ и оплата одной операцией. Заказ, резерв остатка, списание по
техкарте и платёж выполняются в одной транзакции: если что-то не сошлось —
не остаётся ни заказа, ни движения по складу.

**Режим магазина.** Тип заведения («Магазин» или «Кафе и ресторан») задаётся в
панели: «Настройки» → «Тип заведения», при регистрации — тоже. У магазина касса
другая: строка сканера всегда в фокусе, штрихкод сразу кладёт товар в чек
(повторный скан увеличивает количество, `5*` перед кодом — множитель), товар без
штрихкода набирается коротким кодом, названием или одной кнопкой; весовой товар
(«Килограмм» в единицах продажи) — вводом веса, цена считается на лету; плитки с
категориями открываются кнопкой «Плитки». Есть отложенные чеки (F2), оплата одним
касанием (F8 наличные, F9 карта, F10 QR — карта и QR подтверждает кассир после
оплаты на терминале банка), сдача крупно после продажи, звук на каждый скан.
Для кафе ничего не меняется: столы, «в зале» и «навынос» остались как были.

**База штрихкодов.** Чтобы новый магазин не набирал товары с нуля, сканер узнаёт
их по общей базе (подробности — в разделе «База штрихкодов»): отсканировали —
название, объём и полка уже подставлены, остаётся ввести цену. На кассе
управляющий или администратор сканирует незнакомый код, вводит цену, жмёт Enter —
товар создан и лежит в чеке; в панели то же самое делает страница «Товары» →
«Добавить сканером»: скан, цена, Enter, следующий.

**Склад.** Остаток резервируется в момент оформления заказа, неоплаченные
заказы автоматически отменяются через `PENDING_ORDER_TTL_MINUTES` и возвращают
резерв. Приход обновляет себестоимость; цена продажи меняется только если её
задали явно или у категории есть ненулевая наценка. Каждое движение
записывается в журнал.

**Техкарты.** Рецепт блюда списывает ингредиенты в момент оплаты — с точностью
до грамма. Поддерживаются и связанные техкарты, и старый JSON-формат внутри
товара.

**Смены.** Открытие с суммой в кассе, живые итоги по наличным, карте и QR,
расхождение при закрытии. Итоги считаются по заказам смены, а не по времени,
поэтому две открытые кассы не мешают друг другу. Администратор и менеджер
могут закрыть смену, брошенную кассиром.

**Отчёты.** Выручка по часам в часовом поясе заведения, топ товаров, продажи
по сотрудникам, средний чек. Даты трактуются как календарные дни заведения,
а не как UTC.

**Доступы.** Роли `admin`, `manager`, `cashier`, `waiter`, `kitchen`; вход по
паролю или PIN; журнал действий с IP и временем. Назначить роль `admin` может
только администратор.

**Валюта и язык.** Формат денег берётся из настроек заведения (UZS, USD, EUR,
RUB, KZT), интерфейс — русский.

## Локальный запуск

Нужен Node.js 20+.

```bash
cd qwik
cp backend/.env.example backend/.env     # затем отредактировать секреты
npm run setup                            # установка, миграции, demo-данные
npm run dev                              # backend + панель + касса
```

- панель — http://localhost:5173
- касса — http://localhost:5174
- API — http://localhost:3000

Demo-доступы после `npm run setup`: `admin@wespro.com` / `admin123`,
кассир `cashier@wespro.com` / `cashier123` (или PIN `1234`).
Демо-магазин «Продукты «Барака»» (55 товаров со штрихкодами и весовым товаром):
панель `market@wespro.com` / `market123`; на кассе код точки `demo-market`, PIN
Азизы `1234`, Жасура `5678`. Добавить его к уже заполненной базе:
`cd backend && npx tsx prisma/seed-retail.ts` (существующее не трогает).
**Только для локальной разработки** — в продакшене заводите заведение через
форму регистрации.

Лендинг — статическая страница, для просмотра подойдёт любой статический
сервер:

```bash
cd landing && python3 -m http.server 5176
```

Ссылки на панель и кассу подставляются при старте контейнера из переменных
`ADMIN_URL`, `POS_URL`, `CONTACT_EMAIL`, поэтому в исходнике страницы они
выглядят как `${ADMIN_URL}`.

## База данных

Prisma + SQLite. Схема — `backend/prisma/schema.prisma`, миграции —
`backend/prisma/migrations/`. В продакшене они применяются автоматически при
старте контейнера (`prisma migrate deploy`), данные при этом не стираются.

Основные таблицы: `tenants`, `users`, `products`, `categories`, `tech_cards`,
`orders`, `order_items`, `payments`, `cash_shifts`, `stock_receipts`,
`inventory_movements`, `tables`, `receipts`, `audit_logs`.

Посмотреть данные:

```bash
cd backend && npx prisma studio
```

## База штрихкодов

Общая для всех магазинов таблица `catalog_products`: штрихкод → название, бренд,
объём, полка («Напитки», «Сладости»…). Наполняется тремя путями, и сканер
спрашивает их по очереди:

1. **Поставка** — `backend/catalog/catalog.jsonl.gz` (около 137 тысяч позиций,
   2,6 МБ). Это выборка из Open Food Facts и его «сестёр» (Open Beauty Facts,
   Open Products Facts): товары, которые продают в Узбекистане и соседних странах
   (Россия, Казахстан, Турция…), товары с кодами, выданными там (префиксы 478,
   460–469, 868–869 и др.), плюс самые сканируемые в мире. При старте файл
   загружается в базу (несколько секунд, один раз на версию файла — по хэшу),
   сервер отвечает сразу, не дожидаясь загрузки.
2. **Живой поиск** — кода нет в поставке: сервер один раз спрашивает Open Food
   Facts (не чаще 80 запросов в минуту), найденное запоминает, ненайденное не
   спрашивает повторно 12 часов. `CATALOG_LIVE_LOOKUP=off` выключает сеть,
   `OFF_BASE_URL` направляет поиск на другой сервер (так делают тесты).
3. **Магазины** — товар со штрихкодом, внесённый в кассу, попадает в общую базу
   (`source = "crowd"`), и следующий магазин находит его сразу. Передаются только
   штрихкод, название и полка из стандартного списка — **никогда** не цены,
   остатки, продажи и названия собственных категорий. Отключается в «Настройки» →
   «Товары» → «Делиться с общей базой». То, что пришло из поставки или Open Food
   Facts, магазины не перезаписывают; совпадение названия у второго магазина —
   это подтверждение (`confirmations`).

**Охват неполный, и это нормально.** Российские и турецкие товары и мировые
бренды в базе есть хорошо; узбекских брендов в Open Food Facts около тысячи,
непродовольственных товаров мало. Всё, чего нет, добавляется одним сканированием
и потом находится у остальных. Название из базы — подсказка: окно «Новый товар»
показывает, откуда оно, и его можно исправить. Полка подбирается по тегам Open
Food Facts, а если их нет — по ключевым словам в названии.

В базу попадают только настоящие штрихкоды: с верной контрольной цифрой и не из
диапазонов «внутреннего обращения» (200–299 — этикетки весов, купоны и т. п.);
короткий код с клавиатуры («104») и метки магазина никуда не отправляются.

**API** (`/api/catalog`, нужен вход): `GET /lookup?code=…` — что известно о коде
(любая роль), `POST /add` — создать товар магазина по штрихкоду (admin и manager;
если товар был в архиве — вернёт его), `GET /stats` — сколько позиций в базе.

**Обновить поставку** (выкачивает ~1,3 ГБ, минут десять):

```bash
cd backend
npx tsx scripts/build-catalog.ts fetch /tmp/candidates.jsonl
for u in openbeautyfacts openproductsfacts openpetfoodfacts; do
  npx tsx scripts/build-catalog.ts fetch /tmp/candidates.jsonl \
    https://static.$u.org/data/en.$u.org.products.csv.gz
done
npx tsx scripts/build-catalog.ts pack /tmp/candidates.jsonl 10   # 10 — порог «популярности»
```

**Лицензия данных.** Поставка — производная база Open Food Facts: © участники
Open Food Facts, [Open Database License 1.0](https://opendatacommons.org/licenses/odbl/1-0/),
содержимое — Database Contents License 1.0. Производная база распространяется на
тех же условиях (ODbL); отсылка к источнику показана на странице «Добавить
сканером». Подробнее — `backend/catalog/README.md`.

## Диагностика склада

```bash
cd backend && npm run check-inventory
```

Находит то, что ломает учёт: товары с ценой ниже себестоимости, приходы без
движений склада, зависшие резервы неоплаченных заказов.

## Безопасность

- JWT: короткий access-токен и refresh-токен, обмен происходит автоматически.
- Ограничение частоты запросов — по пользователю, а не по IP (за прокси все
  кассы точки выглядят одним адресом).
- Валидация всех тел и query-параметров через Zod; наружу не уходят детали
  запросов к базе.
- PIN и пароли хранятся хешами (bcrypt), в журнале аудита маскируются.
- Данные каждого заведения изолированы: чужие категории, техкарты, столы и
  смены использовать нельзя.
