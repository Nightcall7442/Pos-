# Qwik — POS для торговой точки

Система для магазина и общепита: касса, склад с себестоимостью, техкарты,
кассовые смены и отчётность. Всё работает в браузере — ставить на кассу
ничего не нужно.

- **Сайт:** [www.qwik.uz](https://www.qwik.uz)
- **Панель управления:** [admin.qwik.uz](https://admin.qwik.uz)
- **Касса:** [pos.qwik.uz](https://pos.qwik.uz)

---

## Что внутри

| Папка            | Что это                    | Стек                                                            | Порт (dev) |
|------------------|----------------------------|-----------------------------------------------------------------|-----------|
| `backend/`       | API и база                 | Express 4, Prisma 6, SQLite, Socket.IO, Zod, JWT                | 3000      |
| `frontend-admin/`| панель управления          | React 18, Vite 6, Tailwind 4, React Query, Zustand, Recharts    | 5173      |
| `pos-terminal/`  | POS-терминал (касса)       | React 18, Vite 6, Tailwind 4, React Query, Zustand              | 5174      |
| `landing/`       | сайт-визитка               | статика + nginx                                                  | —         |

Фронтенды ходят к API через собственный прокси (`/api`), поэтому для браузера
это запросы на свой же домен — отдельной настройки CORS в обычной работе
не требуется.

## Возможности

**Касса.** Категории и поиск, весовой товар (цена считается от веса), столы,
клиент, заказ и оплата одной операцией. Заказ, резерв остатка, списание по
техкарте и платёж выполняются в одной транзакции: если что-то не сошлось —
не остаётся ни заказа, ни движения по складу.

**Склад.** Остаток резервируется в момент оформления заказа, неоплаченные
заказы автоматически отменяются через `PENDING_ORDER_TTL_MINUTES` и возвращают
резерв. Приход обновляет себестоимость; цена продажи меняется только если её
задали явно или у категории есть ненулевая наценка. Каждое движение
записывается в журнал.

**Техкарты.** Рецепт блюда списывает ингредиенты в момент оплаты — с точностью
до грамма. Поддерживаются и связанные техкарты, и старый JSON-формат внутри
товара.

**Смены.** Открытие с суммой в кассе, живые итоги по наличным, карте и QR,
расхождение при закрытии. Итоги считаются по заказам смены, а не по времени,
поэтому две открытые кассы не мешают друг другу. Администратор и менеджер
могут закрыть смену, брошенную кассиром.

**Отчёты.** Выручка по часам в часовом поясе заведения, топ товаров, продажи
по сотрудникам, средний чек. Даты трактуются как календарные дни заведения,
а не как UTC.

**Доступы.** Роли `admin`, `manager`, `cashier`, `waiter`, `kitchen`; вход по
паролю или PIN; журнал действий с IP и временем. Назначить роль `admin` может
только администратор.

**Валюта и язык.** Формат денег берётся из настроек заведения (UZS, USD, EUR,
RUB, KZT), интерфейс — русский.

## Локальный запуск

Нужен Node.js 20+.

```bash
cd qwik
cp backend/.env.example backend/.env     # затем отредактировать секреты
npm run setup                            # установка, миграции, demo-данные
npm run dev                              # backend + панель + касса
```

- панель — http://localhost:5173
- касса — http://localhost:5174
- API — http://localhost:3000

Demo-доступы после `npm run setup`: `admin@wespro.com` / `admin123`,
кассир `cashier@wespro.com` / `cashier123` (или PIN `1234`).
**Только для локальной разработки** — в продакшене заводите заведение через
форму регистрации.

Лендинг — статическая страница, для просмотра подойдёт любой статический
сервер:

```bash
cd landing && python3 -m http.server 5176
```

Ссылки на панель и кассу подставляются при старте контейнера из переменных
`ADMIN_URL`, `POS_URL`, `CONTACT_EMAIL`, поэтому в исходнике страницы они
выглядят как `${ADMIN_URL}`.

## Команды

### backend

```bash
npm run dev              # запуск с горячей перезагрузкой
npm run build            # сборка в dist/
npm run start            # запуск собранного кода

npm run db:migrate       # создать миграцию (разработка)
npm run db:deploy        # применить миграции (прод и CI)
npm run db:seed          # demo-данные
npm run check-inventory  # диагностика склада и цен

npm run test             # тесты (vitest)
npm run test:run         # то же, один прогон
```

Тесты поднимают собственный сервер на порту 3100 с отдельной базой
`prisma/test.db` — база разработки не затрагивается.

### фронтенды

```bash
npm run dev      # dev-сервер
npm run build    # сборка в dist/
npm run preview  # просмотр собранного
```

## База данных

Prisma + SQLite. Схема — `backend/prisma/schema.prisma`, миграции —
`backend/prisma/migrations/`. В продакшене они применяются автоматически при
старте контейнера (`prisma migrate deploy`), данные при этом не стираются.

Основные таблицы: `tenants`, `users`, `products`, `categories`, `tech_cards`,
`orders`, `order_items`, `payments`, `cash_shifts`, `stock_receipts`,
`inventory_movements`, `tables`, `receipts`, `audit_logs`.

Посмотреть данные:

```bash
cd backend && npx prisma studio
```

## Диагностика склада

```bash
cd backend && npm run check-inventory
```

Находит то, что ломает учёт: товары с ценой ниже себестоимости, приходы без
движений склада, зависшие резервы неоплаченных заказов.

## Безопасность

- JWT: короткий access-токен и refresh-токен, обмен происходит автоматически.
- Ограничение частоты запросов — по пользователю, а не по IP (за прокси все
  кассы точки выглядят одним адресом).
- Валидация всех тел и query-параметров через Zod; наружу не уходят детали
  запросов к базе.
- PIN и пароли хранятся хешами (bcrypt), в журнале аудита маскируются.
- Данные каждого заведения изолированы: чужие категории, техкарты, столы и
  смены использовать нельзя.

## Деплой

Разворачивается на Railway четырьмя сервисами из одного репозитория —
пошагово, вместе с подключением домена и DNS: **[RAILWAY.md](RAILWAY.md)**.

Локально всё поднимается через Docker Compose:

```bash
docker compose up --build
```

- панель — http://localhost
- касса — http://localhost:8080
- лендинг — http://localhost:8081
