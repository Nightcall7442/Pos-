# План: фронтенд

Касается `frontend-admin/` и `pos-terminal/`. Задачи отсортированы так, что
каждая следующая опирается на предыдущие. Оценки — в днях одного разработчика.

## FE-1. Линтер, формат, CI — ✅ сделано (ветка `chore/toolchain`)

**Проблема.** Ни ESLint, ни Prettier ни в одном приложении. В `backend/package.json`
скрипт `lint` ссылается на несуществующий пакет (`eslint` нет ни в зависимостях,
ни конфига в репозитории) — команда просто упадёт. `.github/` нет: ничего не
проверяется ни локально, ни на PR. 13 000 строк фронтенда держит только `tsc`.

**Что сделать.**
1. Корневой `eslint.config.js` (flat config) на все пакеты:
   `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`,
   `eslint-plugin-react-refresh`.
2. Prettier + `.editorconfig`. Форматирующий коммит отдельно от смысловых —
   иначе первый же дифф будет нечитаемым.
3. Запретить правилами то, что уже болит:
   - `@typescript-eslint/no-explicit-any` — сейчас 61 `any` / `as any`; очаги:
     `pages/ProductEdit.tsx` (15), `pages/Kitchen.tsx` (13), `pages/TechCards.tsx` (10).
     Включить как `warn`, зафиксировать счётчик, довести до нуля.
   - `react-hooks/exhaustive-deps` — 28 `useEffect` без всякой проверки.
4. `.github/workflows/ci.yml`: на каждый PR — `tsc -b` для обоих фронтов,
   `eslint`, `vitest run` для бэкенда. 5–7 минут, блокирует merge.

**Готово, когда.** `npm run lint` и `npm run typecheck` зелёные из корня, CI висит
на PR и краснеет, если их сломать.

### Что вышло на самом деле

Файлы: `eslint.config.mjs`, `.prettierrc.json`, `.prettierignore`,
`.editorconfig`, `.gitattributes`, `.github/workflows/ci.yml`, `CONTRIBUTING.md`,
скрипты в корневом `package.json`.

- **0 ошибок, 382 предупреждения.** Ошибок было 9, все починены или объяснены
  конфигом: пустой `catch` при разборе `localStorage` и `declare namespace Express`
  — осознанные приёмы, они разрешены точечными опциями правил; одна настоящая —
  лишний escape в регулярке `ShopScreen.tsx:107` (`[\d\s.,\-]` → `[\d\s.,-]`,
  поведение то же).
- **Долг зафиксирован планкой.** CI запускает `lint:budget`
  (`eslint . --max-warnings 382`): новое предупреждение делает PR красным, а
  уборка опускает число. Разбивка по правилам — в `CONTRIBUTING.md`.
- **`any` оказалось больше, чем показывал grep:** 110 вместо 61 (grep не видел
  дженерики и приведения в аргументах). Плюс 54 неиспользуемых переменных.
- **185 предупреждений — про подписи полей.** `<label className="label">` стоит
  рядом с `<input className="input">`, но без `htmlFor` и `id`: подпись видно
  глазом, а для скринридера и для клика по тексту её нет. Один компонент
  `FormField` из задачи D-5 снимет почти все.
- **Починен `lint` в бэкенде:** скрипт существовал, но падал — теперь находит
  корневой конфиг и проходит.
- **Синхронизированы три `package-lock.json`:** в них остались старые имена
  пакетов (`wespro-backend` вместо `qwik-backend` и так далее) — для `npm ci` в
  CI это лишний риск.
- **ESLint пришлось оставить на 9.x:** `eslint-plugin-jsx-a11y` 6.10.2 не
  поддерживает 10.x. Причина записана в конфиге и в `CONTRIBUTING.md`.

**Проверено:** `npm run lint:budget`, `npm run typecheck`, `npm test`
(после фикса `fix(tests)` — набор раньше не запускался на Windows) и
`vite build` обоих фронтендов — всё зелёное.

**Тест-харнесс на Windows** (`process.kill(-pid)` и `spawn("npx")`) починен
отдельным коммитом `fix(tests)`.

## FE-2. Общий пакет вместо трёх копий — 2 дня

**Проблема.** Типы домена написаны руками дважды: `frontend-admin/src/services/index.ts`
(286 строк) и `pos-terminal/src/types/index.ts` (192 строки) — и третий раз живут
в `prisma/schema.prisma` (24 модели). Утилиты продублированы: `utils/national.ts`
и `hooks/useBurstGuard.ts` совпадают байт в байт, а `utils/money.ts` и
`hooks/useMoney.ts` уже разошлись. В кассе есть `moneyParts`, `quickCashAmounts`
и `round2`, в панели их нет. `round2` намеренно повторяет серверный
`stock.helpers.round2` — то есть это контракт с бэкендом, и он существует только
в одном из двух приложений.

**Что сделать.**
1. npm workspaces в корневом `package.json`, новый пакет `packages/shared/`.
2. Перенести туда версию кассы (она полная): `money.ts`, `national.ts`,
   `useBurstGuard.ts`, `useMoney.ts` и типы домена. Оба приложения импортируют
   `@qwik/shared`.
3. Типы не писать руками, а генерировать из `schema.prisma`
   (`prisma-generator-typescript-interfaces` или свой скрипт) и проверять в CI,
   что сгенерированное совпадает с закоммиченным.
4. В комментарии к `round2` оставить ссылку на серверный аналог — чтобы правили
   оба места одновременно.

**Готово, когда.** `grep -r "export function money" frontend-admin pos-terminal`
не находит ничего, а смена валюты в настройках меняет формат одинаково в кассе и
в панели.

## FE-3. Починить обновление токена в панели — полдня

**Проблема.** `frontend-admin/src/services/api.ts` дергает `/auth/refresh`
независимо на каждый 401. Dashboard открывает несколько запросов сразу — при
истёкшем токене уйдёт столько же refresh, сервер ротирует токен, лишние получат
отказ и `window.location.href = "/login"`. Плюс перехватчик срабатывает и на сам
вход: неверный пароль → попытка refresh → редирект вместо сообщения об ошибке.

**Что сделать.** Перенести готовое рабочее решение из
`pos-terminal/src/services/api.ts`: один общий `refreshing: Promise<string> | null`
на все параллельные 401 и исключение урлов `/auth/(login|login-pin|refresh)`.
Дальше — вынести клиент в `packages/shared` (после FE-2), чтобы расхождение не
повторилось.

**Заодно.** Токены лежат в `localStorage` в обоих приложениях
(`store/authStore.ts` через `persist`; в кассе — ключи `pos-token` / `pos-refresh`).
Это рабочий компромисс, но refresh-токен стоит перевести в httpOnly-cookie:
тогда XSS перестаёт означать бессрочный доступ. Требует правок бэкенда — отдельной
задачей.

**Готово, когда.** Протухший токен + 5 параллельных запросов → ровно один POST
`/auth/refresh` и ни одного редиректа. Неверный пароль → текст ошибки на экране,
страница не перезагружается.

## FE-4. Тесты там, где ошибка стоит денег — ✅ сделано (ветки `test/frontend`, `test/e2e`)

`npm run test:frontend`. 58 тестов:

Проверено выключением: без округления по строкам падает тест итога; со
старым useSocket (ref вместо состояния) падают оба теста подключения.

**Сквозной сценарий — ✅ (ветка `test/e2e`):** `e2e/cashier.spec.ts`, 2 теста —

## FE-6. Офлайн-режим кассы — 5 дней

**Проблема.** PWA нет вообще: ни манифеста, ни service worker — в
`pos-terminal/public/` лежит только `favicon.svg`. Шрифты тянутся с
`fonts.googleapis.com` прямо из `index.html`, поэтому первый экран ждёт внешний
домен. Пропал интернет — магазин не продаёт. Для кассы это дефект номер один по
деньгам.

**Что сделать.**
1. `vite-plugin-pwa`: манифест (standalone, обе ориентации, иконки 192/512),
   precache бандла. Касса запускается без сети.
2. Шрифты положить в `public/fonts` и раздавать со своего домена.
3. Кэшировать каталог в IndexedDB при каждой успешной загрузке; без сети касса
   открывает прошлый каталог только для чтения.
4. Очередь продаж: продажа без сети пишется в IndexedDB как «не отправлена»,
   интерфейс честно показывает «N чеков ждут отправки», при восстановлении связи
   они уходят по одному с идемпотентным ключом.
5. ✅ Бэкенд уже принимает `Idempotency-Key` на продаже, оплате и приходе
   (B-2). Касса должна слать ключ: один на корзину, тот же при повторе.

**Риск.** Резерв и списание по техкарте считает сервер, поэтому офлайн-продажа
может уйти в минус по остатку. На первом шаге: разрешать офлайн только для
товаров, уже известных кассе, и помечать такие заказы флагом — чтобы расхождение
было видно в отчёте, а не пряталось.

**Готово, когда.** Выключить Wi-Fi на планшете → провести 3 продажи → включить →
все три появились в панели по одному разу.

## FE-7. Производительность и устойчивость — 1 день

1. Ленивая загрузка роутов. Сейчас `vite build` панели выдаёт **один файл
   930 КБ (262 КБ gzip)** и сам предупреждает о размере чанка. В
   `frontend-admin/src/App.tsx` все 20 страниц
   импортируются статически, поэтому `recharts` (нужен только в `Reports.tsx`) и
   `date-fns` попадают в начальный бандл, даже когда открыт только логин.
   `React.lazy` + `Suspense` + `manualChunks` под `recharts`.
2. `ErrorBoundary` на `Layout` и на каждый экран кассы. Сейчас любая ошибка
   рендера — белый экран на кассе посреди смены.
3. Роут `*` → 404. Сейчас неизвестный адрес в панели даёт пустой `<main>`.
4. Виртуализация каталога (`@tanstack/react-virtual`): в демо уже 55 позиций, у
   реального магазина их тысячи.

**Готово, когда.** Начальный бандл панели меньше 250 КБ gzip, а ошибка в одном
экране не гасит приложение целиком.

## FE-8. Узбекский язык — 3 дня

**Проблема.** Около 4 300 кириллических вкраплений прямо в JSX, i18n-библиотеки
нет. Продукт продаётся в Узбекистане, где узбекский на латинице — условие
продажи, а не улучшение.

**Что сделать.** `i18next` + `react-i18next` в `packages/shared`, локали `ru`,
`uz`, `en` на будущее. Вынос строк: черновик скриптом по JSX-литералам, дальше
руками по экранам — сначала касса (её видит кассир каждый день), потом панель.
Выбор языка — в настройках заведения и переключателем на экране входа.

**Осторожно.** На экранах входа и в `landing/` заголовок серифный, с `<em>`-акцентом
внутри фразы. При переводе ритм строки ломается — это дизайнерская работа,
см. `D-5` в [плане дизайна](02-design.md).
